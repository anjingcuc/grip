# 可选的攀岩者检测与保色（人物 = 一等可选对象）

**状态**: accepted

项目场景原本定为"输入照片没有攀爬者"，不做人物检测（AGENTS.md 已定型决策）。实际使用中部分照片确实有攀岩者，而攀岩者不希望自己被灰度化——需要人物作为可选对象参与渲染。

决策：**复用既有"检测器自提示 + EdgeSAM"管线**（调研报告 §4.3）：COCO 预训练 YOLO11n（person = 第 0 类）出人物框，用同一张图的 EdgeSAM embedding 框提示解码出人物轮廓，掩码存入 `Analysis.person` 并随会话持久化；渲染新增 `person_keep` 开关（默认 1=保色），人物掩码在羽化前并入保色掩码。缺失人物模型时功能静默关闭，主路不受影响。

选它的理由：零新框架（tract 推理与 SAM 分割全复用）、人物是 COCO 最成熟的类别、检测+解码只增加一次 YOLO 推理（~150ms）与至多 3 次 decoder 调用。

## Considered Options

- **YOLO-seg 实例分割直接出人物掩码**：省一步 SAM，但 YOLO-seg 掩码边界粗糙，且要引入 proto-mask 组装的全新后处理。本项目的 EdgeSAM 框提示质量已在岩点上验证，人物复用同路更稳。
- **MediaPipe Selfie Segmentation 等专用人像分割**：面向自拍半身像优化，攀岩全身照姿态/尺度不匹配，且引入新运行时。拒绝。
- **不重训岩点模型加人物类**：ChalkGPT 权重是公开第三方的，混入人物类需要合并数据集重训，成本高、收益低。拒绝。

原"无人物检测"决策就此修订为：无人物**强制**检测——人物检测为可选增强，默认模型齐备时开启。
