# 区分抹除（误检抹平）与排除（颜色误判保留灰点）

**状态**: accepted

"排除"操作原本身兼两职，且语义错误：用户排除一个岩点，可能是"污渍/螺丝孔被误检为岩点"（期望该区域被抹平进墙面、画面更整洁），也可能是"确实是岩点、只是颜色误判"（期望保留灰度可见）。旧实现把两类都塞进 `excluded` 一个集合，只在 `bg_fill>0` 时才填掉——GUI 净化滑杆未上线前，被排除的误检点始终以灰点残留，违背"排除误检 = 抹掉"的直觉。

决策：拆成两个互斥操作（GitHub issue #4）。

- **抹除 Erase**：判定"这不是岩点"。该区域视为非岩点区域，**始终满强度净化抹平**——与 `bg_fill` 滑杆解耦，滑杆为 0 也立即抹掉。理由：抹除是点对点的显式整洁指令，用户操作意图就是"让这块消失"，不该要求先去开全局净化。
- **排除 Exclude**：判定"是岩点但颜色误判/不入线路"。岩点**保留在填充并集内受保护**，不被抹平，只走与未选中岩点一致的灰度化。

数据模型：会话新增 `erased` 集合（serde 默认空，兼容老会话）；老会话的 `excluded` 落入新"排除"语义（橡皮擦工具的主要用途本就是颜色误判），无需迁移。GUI 橡皮擦 `[4]` 改为抹除，新增工具 `[5]` 排除；CLI 会话 `--remove`=排除、新增 `--erase`=抹除。

## Considered Options

- **排除点跟随全局 `bg_fill` 强度**（旧行为）：滑杆为 0 时误检点仍是灰点，与用户"使画面更整洁"的期望直接冲突。拒绝。
- **抹除强度保底折中**（如 max(bg_fill, 0.8)）：避免满强度抹平斑块与未净化脏墙的反差，但引入说不清的魔法数，且 0.8 与 1.0 的视觉差异微弱。拒绝，取满强度。
- **单一集合 + 操作时询问类型**：每次橡皮擦点击都弹问"是误检还是颜色误判"，打断批量处理节奏。拒绝，改为两个工具/两个参数。
