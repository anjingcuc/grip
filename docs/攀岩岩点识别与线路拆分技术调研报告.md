# 室内攀岩照片岩点识别与线路拆分：技术调研报告

## 摘要（TL;DR）

你设想的“拍照 → 自动识别全部岩点 → 按颜色拆分线路 → 选中线路彩色高亮、其余灰度 → 用户可交互修正”的系统，**在技术上完全可行，且已有多篇论文、多个开源项目和多款商业产品验证了其中每一个环节**。综合调研结论如下：

- **岩点检测的主路线应基于深度学习的实例分割而非颜色阈值或传统边缘检测**。斯德哥尔摩大学 2024 年的对照学位论文直接将 YOLO 与“边缘检测+斑点检测”做了统计比较，结论支持机器学习方法作为标准路线；海德堡大学的项目同时实现了学习与非学习两条路线，发现学习路线“在精度上远优”([GitHub: xiaoxiae](https://github.com/xiaoxiae/Indoor-Climbing-Hold-and-Route-Segmentation), [SU DiVA](https://su.diva-portal.org/smash/get/diva2:1955778/FULLTEXT01.pdf))。
- **你提出的“先轮廓、后颜色”的两阶段设计，与学界和工业界的主流做法一致**：UCSD 的系统用 YOLO 检测岩点（mAP 96.3%）后，再用独立的颜色模块判色（准确率 99.3%）([UCSD](https://kastner.ucsd.edu/ryan/wp-content/uploads/sites/5/2022/06/admin/rock-climbing-coach.pdf))；商业产品 Stōkt 的“自动墙面扫描”和 OwnClimb 的检测 API 也都是“多边形+置信度+主色”的输出结构([Stōkt](https://play.google.com/store/apps/details?id=com.getstokt.stokt), [OwnClimb](https://ownclimb.com/))。
- **针对镁粉/鞋胶染色问题，关键不是“更准的颜色检测”，而是“检测与颜色解耦 + 掩码内部稳健取色”**：用与颜色无关的实例分割确定轮廓（染色不改变岩点几何形状），再在掩码内部用直方图众数或 Lab 空间中位数等抗污染统计量取色，即可绕过“半个岩点被染色导致漏检”的问题([NeuralClimb](https://github.com/scsukas8/NeuralClimb))。
- **SAM 类模型不适合直接承担全自动检测主路**（其“分割一切”模式无类别语义、会产生大量墙面/螺栓孔碎片掩码，且对密集小物体有漏检与合并相邻实例的记录），但它（尤其是 **EdgeSAM**，iPhone 14 上 38.7 FPS）是**交互修正环节的最佳引擎**：用户点一下/框一下漏检岩点，局部重新分割，毫秒级返回([arXiv: EdgeSAM](https://arxiv.org/abs/2312.06660), [MDPI: MVSegNet](https://www.mdpi.com/1999-4893/19/1/23))。
- **训练数据不需要从零开始**：Roboflow Universe 上有多个 CC BY 4.0 的岩点实例分割数据集（单项目可达数千张），Kaggle 上有海德堡项目发布的岩点分割数据集和模型权重，配合 50–150 张自己岩馆的照片做微调即可落地([Roboflow: Pwals](https://universe.roboflow.com/pwals/bouldering-holds-9wavr), [Kaggle](https://www.kaggle.com/datasets/tomasslama/indoor-climbing-gym-hold-segmentation), [antonylanglois.com](https://www.antonylanglois.com/en/blog/fine-tuning-yolo-climbing-holds))。
- **本地计算可行**：YOLO11n-seg 在纯 CPU（ONNX）上单帧约 66 ms，EdgeSAM 在 iPhone 14 上达到实时；整条管线（检测→取色→聚类→渲染）在消费级笔记本或旗舰手机上可以做到“拍照后 1–2 秒出结果，交互修正即时响应”([Ultralytics 基准](https://github.com/eecn/yolov8-ncnn-inference), [arXiv: EdgeSAM](https://arxiv.org/abs/2312.06660))。

## 1. 任务拆解与技术挑战

### 1.1 系统功能的形式化拆解

把需求翻译成计算机视觉的语言，系统实际上由四个串行子任务加一个闭环组成：**实例分割**（找出每个岩点的像素级轮廓）、**属性估计**（对每个轮廓估计其“真实颜色”，对抗染色）、**聚类分组**（把颜色相近的岩点聚成线路，并处理同色异线、一线多色的情况）、**可视化渲染**（选中集合彩色、其余灰度的掩码合成），以及贯穿始终的**人机交互修正**（漏检补标、误检删除、归属改判）。值得注意的是，2026 年发表于 SSRN 的一篇论文把这一领域的问题结构总结为同样的观点：室内攀岩墙感知“不是一个单一的分割问题，实际系统必须解决至少两个耦合任务”——岩点分割与线路分割([SSRN: Liang 2026](https://papers.ssrn.com/sol3/papers.cfm?abstract_id=7124038))。

这个拆解方式决定了技术选型的边界：检测环节需要的是**类别无关但形状敏感**的实例分割器（岩点形状各异、尺度跨度大、相互紧贴），而颜色分类环节需要的是**对局部污染稳健**的取色与聚类算法。两类问题使用完全不同的技术栈，这正是你“先轮廓后颜色”直觉的正确性所在——它把深度学习用在它最擅长的地方（形状与语义先验），把传统统计用在它最稳妥的地方（小样本颜色估计），避免了让单一颜色阈值同时承担“找到岩点”和“区分线路”两个相互冲突的目标。

### 1.2 四个核心挑战的文献证据

**染色与污染**。镁粉（碳酸镁）会在岩点表面形成白色薄膜，攀岩鞋橡胶会留下黑色磨痕，二者都会改变岩点的局部颜色但不改变其轮廓。NeuralClimb 项目在实践中验证了对应的工程对策：先做中值滤波“去除镁粉和杂质的噪声，同时保留甚至锐化岩点与墙面之间的边缘”，再进行轮廓提取；取色时不用均值而是对掩码内像素做直方图量化后取众数，以抵御局部污染([NeuralClimb](https://github.com/scsukas8/NeuralClimb))。UCSD 团队则直接记录了镁粉墙面的困难：“墙面非常粉化（chalky），连人眼都难以区分岩点和墙面”，这是他们放弃传统方法转投 YOLO 的直接原因([UCSD](https://kastner.ucsd.edu/ryan/wp-content/uploads/sites/5/2022/06/admin/rock-climbing-coach.pdf))。

**杂色干扰（误检源）**。墙面上的色带贴纸、品牌 Logo、地垫、相邻线路的脚点贴片都会被纯颜色方法误判为岩点。UCSD 团队在对比实验中发现，Canny 边缘+斑点检测“在岩点大小相近的干净墙面上效果尚可”，但在真实墙面上失效([UCSD](https://kastner.ucsd.edu/ryan/wp-content/uploads/sites/5/2022/06/admin/rock-climbing-coach.pdf))；NeuralClimb 同样记录了“阴影偶尔被误分类为岩点、与墙面颜色接近的岩点会漏检”([NeuralClimb](https://github.com/scsukas8/NeuralClimb))。这意味着“用颜色确认岩点”必须是**在轮廓候选之上的验证步骤**，而不是候选生成步骤——与你的设计判断一致。

**小目标与密集排布**。一张整墙照片中，远处的脚点可能只占几十个像素。通用检测器在输入缩放后会丢失这类目标，标准对策是推理时切片（SAHI），它能在不重训模型的情况下显著提升小目标召回：公开报告中 YOLOv11 配合 SAHI 在同一场景多检出 37% 的目标，另有报告称召回率从 31.8% 提升到 86.4%([GitHub: YOLOv11+SAHI](https://github.com/Ayushkumarsingh24/YOLOv11-and-SAHI-for-improved-small-object-detection-), [Labellerr](https://www.labellerr.com/blog/small-object-detection/))。

**同色异线与相似色线路**。岩馆常见两条线路颜色相近（如绿色与青绿色），或者同一颜色被用于两条不同线路。UCSD 团队用 11 类颜色分类器时就观察到“绿色和青绿色岩点都被判为绿色，尽管它们应属于两条不同线路”，并指出解决办法是改用**颜色频率分析（聚类）而非固定类别分类**([UCSD](https://kastner.ucsd.edu/ryan/wp-content/uploads/sites/5/2022/06/admin/rock-climbing-coach.pdf))。这一点对工程设计影响重大：颜色空间的“类别数”必须是每张图自适应的，而不是全局固定的。

## 2. 直接相关的学术研究综述

### 2.1 岩点检测与分割专题研究

这个细分领域的文献虽然总量不大，但已经形成了清晰的方法演进脉络：传统 CV（2016 前后）→ YOLO 系检测（2019 起）→ 实例分割与系统级管线（2022 起）→ 数据集与基准建设（2023 起）。下表汇总了与“岩点检测/分割”直接相关的主要公开研究。

| 工作（年份，出处） | 任务设定 | 方法 | 关键结果/结论 |
|---|---|---|---|
| NeuralClimb（2016，GitHub 项目） | 岩点定位+颜色分类 | 中值滤波+Canny+轮廓+凸包+Blob；HLS 直方图众数取色+K-means 分组 | 在 2D 图像上“检测并颜色分类，错误很少”；承认阴影误检、近墙色漏检([GitHub](https://github.com/scsukas8/NeuralClimb)) |
| Computer Vision Based Indoor Rock Climbing Analysis（2022，UCSD） | 岩点检测+颜色分类+攀爬分析 | YOLO 检测；11 类颜色神经网络分类器（标注 2759 个岩点） | 检测 mAP **96.3%**，颜色分类准确率 **99.3%**；指出分类器无法区分相近色线路([UCSD PDF](https://kastner.ucsd.edu/ryan/wp-content/uploads/sites/5/2022/06/admin/rock-climbing-coach.pdf)) |
| Indoor Climbing Hold and Route Segmentation（2023，海德堡大学） | 岩点分割+线路分割双任务 | 学习路线（实例分割）与非学习路线（传统分割）对照实现 | “学习路线在精度上远优，但需要手工标注数据”；公开了数据集与模型权重([GitHub](https://github.com/xiaoxiae/Indoor-Climbing-Hold-and-Route-Segmentation), [Kaggle](https://www.kaggle.com/datasets/tomasslama/indoor-climbing-gym-hold-segmentation)) |
| YOLO vs Edge Detection for Climbing-hold Detection（2024，斯德哥尔摩大学学位论文） | 两种范式的统计比较 | YOLO（机器学习）vs 边缘+斑点检测（传统 CV） | 指出领域缺乏标准化比较，以统计检验方式论证机器学习方法的优势([SU DiVA](https://su.diva-portal.org/smash/get/diva2:1955778/FULLTEXT01.pdf)) |
| Deep Learning Approaches for Indoor Climbing Hold and Route Segmentation（2026，SSRN） | 岩点+线路分割方法综述/研究 | 将任务定义为“层级感知问题” | 结论：深度检测器与实例分割器可定位岩点，框检测或分割可作为线路分组的前级([SSRN](https://papers.ssrn.com/sol3/papers.cfm?abstract_id=7124038)) |
| Deep Neural Strategies for Uncovering Climbing Elements and Mapping Route Patterns（2025） | 岩点定位与线路模式映射 | 对比 Blob 检测/边缘检测与深度学习 | 传统方法用 OpenCV 实现，深度学习用于岩点检测([IJME](https://www.intmaritimeengineering.org/index.php/ijme/article/view/1663)) |
| Towards Automatic Object Detection and Activity Recognition in Indoor Climbing（2024，Sensors） | 第一人称视角岩点检测+抓握识别 | 定制 YOLOv5+眼动追踪 | 证明移动端/可穿戴视角下深度学习岩点检测可用([PMC](https://pmc.ncbi.nlm.nih.gov/articles/PMC11479384/)) |
| Deep Learning for Automated Localization of Gaze Points and Climbing Holds（2024，IPTA） | 岩点定位+注视点定位 | 深度学习检测与追踪 | 提出在全局墙面坐标系中定位被注视岩点的方法([ResearchGate](https://www.researchgate.net/profile/William-Pantry/publication/386063281_Deep_Learning_for_Automated_Localization_of_Gaze_Points_and_Climbing_Holds/links/681db65fdf0e3f544f5325a1/Deep-Learning-for-Automated-Localization-of-Gaze-Points-and-Climbing-Holds.pdf)) |
| Speed climbing 视频对齐管线（2021，布尔诺理工大学硕士论文） | 速度攀岩岩点检测+配准 | 微调目标检测模型+光流跟踪+Coherent Point Drift | 形成“检测→跟踪→映射到参考墙”的完整管线([MUNI](https://is.muni.cz/th/zp7vz/speed_climbing_mapping.pdf)) |

从上表可以提炼出一个共识性结论：**凡是严肃的对比研究，最终都选择了深度学习方法作为检测主路，传统 CV 方法被定位为基线或 fallback**。UCSD 的工作尤其值得细读，因为它几乎是你的系统的“论文版原型”：同样是“检测先行、颜色殿后”，同样面向手机拍摄的照片/视频，并且给出了可复现的量化指标（96.3% mAP、99.3% 颜色分类准确率）。它的局限也同样有参考价值——颜色分类器的固定类别设定无法处理相近色线路，这直接指向第 5 节将讨论的“聚类优先于分类”的设计原则。

### 2.2 相邻领域的可迁移研究

攀岩动作分析领域的研究虽然目标不是“拆分线路”，但其中大量工作都必须先解决岩点检测，因此其工程经验可以直接迁移。Beta Caller（WSCG 2024）用 YOLOv8 自训练岩点检测器+ViTPose 姿态估计，构建了面向视障攀岩者的实时指引系统，肢体预测准确率 80.08%，下一岩点定位框误差仅 6.79%([WSCG 2024](http://wscg.zcu.cz/WSCG2024/JWSCG-2024/A61-2024.pdf))。Climb-o-Vision（CHI 2022）用 YOLOv5 检测岩点并通过舌部电触觉界面引导视障用户([CVPRW 2025 综述引用](https://openaccess.thecvf.com/content/CVPR2025W/CVSPORTS/papers/Maschek_The_Way_Up_A_Dataset_for_Hold_Usage_Detection_in_CVPRW_2025_paper.pdf))。奥地利 TU Wien 的硕士论文则用 YOLOv3 检测攀岩者并据岩点覆盖率自动判定比赛得分([TU Wien](https://repositum.tuwien.ac.at/handle/20.500.12708/20091))。速度攀岩方向，Pandurević 等人先用特征与关键点算法做视频分析（Sensors 2022），2025 年的后续工作已改用 YOLOv8 识别速度攀岩岩点([Sensors 2022](https://www.mdpi.com/1424-8220/22/6/2251), [Bioengineering 2025](https://www.mdpi.com/2306-5354/12/9/957))。

数据集方面，最值得注意的是 **The Way Up**（CVPR 2025 体育视觉 workshop）：22 段标注攀爬视频，包含岩点位置、使用顺序与时间戳，专为“普通硬件可运行”的方法评估而建([arXiv](https://arxiv.org/html/2505.12854v1))；以及 CVPR 2023 的 **CIMI4D**，一个大型多模态攀爬动作数据集([IEEE](https://doi.org/10.1109/CVPR52729.2023.01247))。这两个数据集面向的是动作/姿态分析，对你的单照片任务而言价值在于：其标注中包含了岩点级 ground truth，可作为额外训练数据来源；此外 2026 年还有一项工作直接基于基础姿态模型实现了“免训练”的岩点使用检测，说明该领域的工具链仍在快速演进([arXiv 2026](https://arxiv.org/html/2609.30026v1))。

这些项目合起来覆盖了管线中的每一个环节，且彼此互补：antonylgs 项目贡献了“数据清洗与微调工程”的完整经验（合并多源数据集时类名不一致、空标注、退化多边形等坑，以及“按照片而非按岩点划分数据集以防泄漏”的关键实践）([作者博客](https://www.antonylanglois.com/en/blog/fine-tuning-yolo-climbing-holds))；tonylay7 项目贡献了“掩码→颜色→线路”的具体算法（RGB K-means 分组、黑白特判、T 螺母孔尺度归一化）；ChalkGPT 贡献了 CLIP 零样本颜色分类和 DBSCAN 聚类的组合思路。工程上可以把三者拼成一个高起点的 baseline。

### 3.2 公开数据集

数据是该项目的最大杠杆，好消息是已有相当规模的公开标注数据。Roboflow Universe 上有多个岩点数据集，其中 Blackcreed 的 “Climbing Holds and Volumes” 已被多篇论文引用([Roboflow](https://universe.roboflow.com/blackcreed-xpgxh/climbing-holds-and-volumes))；Pwals 的 “Bouldering holds” 是实例分割（多边形）格式、CC BY 4.0 许可([Roboflow](https://universe.roboflow.com/pwals/bouldering-holds-9wavr))；Climb AI 的 “Hold Detector” 附带预训练模型和 API([Roboflow](https://universe.roboflow.com/climb-ai/hold-detector-rnvkl))。antonylgs 作者实际合并了三个 Roboflow 数据集得到 5619 张图，清洗后按 4446/555/555 划分训练/验证/测试([作者博客](https://www.antonylanglois.com/en/blog/fine-tuning-yolo-climbing-holds))。海德堡项目在 Kaggle 发布的数据集则同时包含两个岩馆（相机与手机两种拍摄条件）的 VIA 标注和最佳模型权重([Kaggle](https://www.kaggle.com/datasets/tomasslama/indoor-climbing-gym-hold-segmentation))。

需要注意两类风险。其一，**公开数据的分布偏置**：Roboflow 上的数据集多来自少数岩馆，岩点材质、墙面颜色、拍摄距离与你的目标场景未必一致，公开数据适合冷启动，但要达到产品级精度仍需 50–150 张自有场景照片微调——这正是 antonylgs PRD 中明确写入的策略([PRD](https://github.com/antonylgs/yolov11-climbing-holds-detector/blob/main/PRD.md))。其二，**许可合规**：商用产品需逐个核对数据集许可（CC BY 4.0 通常允许商用但需署名），并保留来源记录。一个降低标注成本的成熟技巧是**模型辅助标注**：先用公开数据训练初版模型，让它在你的照片上预画轮廓，人工只做修正，可比纯手标快 5–10 倍([LESSON.md](https://github.com/antonylgs/yolov11-climbing-holds-detector/blob/main/LESSON.md))。

## 4. 岩点检测与分割的模型选型

### 4.1 传统计算机视觉路线：可用作基线与 sanity check

传统路线的典型管线是“中值滤波去镁粉噪声 → Canny 边缘（用 Otsu 自适应阈值适应光照）→ 轮廓提取 → 凸包补全缺口 → Blob 检测过滤面积/惯性比过小的区域”([NeuralClimb](https://github.com/scsukas8/NeuralClimb))。它的优点是零训练成本、完全可解释、单帧毫秒级；缺点在多篇文献中被一致记录：对粉化墙面失效、丢失颜色信息（灰度化）、漏检与墙面同色的岩点、把阴影误检为岩点、难以适配各种形状的岩点([UCSD](https://kastner.ucsd.edu/ryan/wp-content/uploads/sites/5/2022/06/admin/rock-climbing-coach.pdf), [NeuralClimb](https://github.com/scsukas8/NeuralClimb))。无监督分割家族（SLIC 超像素、Felzenszwalb 图分割、Quickshift、标记分水岭）可以作为补充候选生成器，scikit-image 对这些方法有现成的对比实现与可视化([scikit-image](https://scikit-image.org/docs/0.25.x/auto_examples/segmentation/plot_segmentations.html))。

结论是：传统方法不适合作为产品主路，但有两个不可替代的用途——一是在项目第一天就搭起来作为**端到端管线的占位符**（让颜色聚类、交互界面先行开发）；二是作为**故障分析工具**（当深度模型漏检时，用传统方法在同一区域跑一遍，可以快速判断是数据问题还是场景本身病态）。

### 4.2 YOLO 实例分割：检测主路的最佳选择

实例分割版 YOLO（YOLOv8-seg / YOLO11-seg）是当前最匹配该任务的模型族：单阶段、输出像素级掩码、训练生态成熟（Ultralytics）、导出格式齐全（ONNX/CoreML/TFLite/NCNN）。官方基准显示 YOLO11n-seg 仅 2.9M 参数、CPU（ONNX）单帧 65.9 ms、T4 TensorRT 1.8 ms；YOLO11x-seg 掩码 mAP 50-95 达 43.8 但 CPU 延迟升至 664 ms([Ultralytics 基准](https://github.com/eecn/yolov8-ncnn-inference))。上一代 YOLOv8n-seg 的对应数字是 3.4M 参数、CPU 96.1 ms([YOLOv8 基准](https://github.com/ZXB6/yolov8-ncnn-))。对“拍照后一次性分析”的场景，n/s 档模型的 CPU 延迟完全可接受；若要做实时取景预览，则可上 GPU/NPU 或用 n 档+INT8 量化。

![模型性能对比](fig_models.png)

训练侧的关键决策有三点。第一，**类别设定建议为单类（hold）或双类（hold/volume）**：岩点类型（jug/crimp/sloper）细分会显著增加标注难度且对线路拆分无益，antonylgs 的 PRD 明确把类型分类列为非目标、把 volume 并入 hold([PRD](https://github.com/antonylgs/yolov11-climbing-holds-detector/blob/main/PRD.md))。第二，**整墙照片必须处理小目标问题**：要么训练时直接用较大输入分辨率（1280），要么推理时启用 SAHI 切片——后者不重训模型即可显著恢复小岩点召回，代价是推理时间随切片数近似线性增长，且跨切片合并需要额外的 NMS 去重([Labellerr](https://www.labellerr.com/blog/small-object-detection/), [TechnoLynx](https://www.technolynx.com/post/sahi-yolo-slicing-aided-inference-for-small-object-detection/))。第三，**数据泄漏防护**：必须按“整张照片”而非按“岩点”划分训练/验证集，否则同一面墙的岩点同时出现在两侧会让验证指标虚高([作者博客](https://www.antonylanglois.com/en/blog/fine-tuning-yolo-climbing-holds))。

### 4.3 SAM 家族：不是检测主路，而是交互修正引擎

Segment Anything 系列对本项目的价值需要分场景评估。其“分割一切”（Automatic Mask Generation）模式在 32×32 网格点上提示并做 NMS，输出的是**类别无关**的掩码集合，且不保证覆盖整图([arXiv: Region-Based Representations Revisited](https://arxiv.org/pdf/2402.02352))。对本任务这意味着两个问题：一是输出里混有墙面区域、螺栓孔、贴纸等大量非岩点掩码，需要额外的分类/过滤步骤；二是对密集小物体的稳定性有公开的负面记录——海事船舶分割团队在构建数据集时实测发现 SAM1/SAM2“经常漏掉小船只，并倾向于把相邻或重叠的船合并为一个掩码”，最终放弃用 SAM 辅助标注([MDPI: MVSegNet](https://www.mdpi.com/1999-4893/19/1/23))。攀岩墙恰恰是“密集、相邻、尺度跨度大”的场景，因此不建议把 SAM 自动模式作为检测主路。

但 SAM 家族在另外两个位置上价值极高。其一是**交互修正**：用户点选/框选一个漏检岩点，SAM 的点/框提示接口直接返回该物体的掩码，这比让用户手工描边体验好一个数量级。其二是**作为检测器的掩码升级器**：YOLO 检测框作为 SAM 的框提示，可以换取更精确的边界。这条“YOLO 自提示+微调轻量 SAM”的路线已在工业裂缝检测上被完整验证——CrackESS 系统用 YOLOv8 生成提示框、ConvLoRA 微调 EdgeSAM 做分割，在 PC 上处理 1024×1024 图像达 46 FPS、Jetson Orin Nano 上 8 FPS([arXiv: CrackESS](https://arxiv.org/html/2412.07205v3))。选型上，移动端首选 **EdgeSAM**（纯 CNN 编码器，iPhone 14 上 38.7 FPS，比 MobileSAM/EfficientSAM 快 7 倍以上，框提示 mIoU 与原版 SAM 仅差 0.6）([arXiv: EdgeSAM](https://arxiv.org/abs/2312.06660))；桌面端如果追求最高边界质量，可以用原版 SAM ViT-H 或 HQ-SAM。SAM 2 的视频分割能力对本项目属于超需求（单照片场景），其图像模式可作为 SAM 的等价替代([ChalkGPT](https://github.com/GabiShahmayster/ChalkGPT))。

### 4.4 开放词汇检测与其他候选方案的评估

开放词汇检测器（Grounding DINO、YOLO-World）支持“输入文本‘climbing hold’直接出框”，看似免训练，实际不适合作为主路：Grounding DINO-L 的零样本 COCO AP 为 52.5% 但 V100 上仅约 3 FPS，YOLO-World 达 52–74 FPS 但零样本精度明显更低（LVIS AP 26.2–35.4%），且“climbing hold”这类长尾概念的表述敏感性会进一步拉低实际精度([RoboLabs](https://www.robolabs.ai/resources/blog/open-vocabulary-foundation-models-vision-language))。它们的合理用途有两个：一是**冷启动标注**（用“a climbing hold”提示预标自有照片，人工修正后进入微调集）；二是**处理极端形状**（如全新材质的造型点）时的兜底召回。两阶段检测器 Mask R-CNN（Detectron2）已被证明可完成本任务([tonylay7](https://github.com/tonylay7/bouldering_route_classification))，但推理成本高于同精度 YOLO-seg，新项目无必要选用。

综合而言，检测环节推荐的主从结构是：**YOLO11-seg（或 YOLOv8-seg）微调模型为主路，EdgeSAM 为交互修正与边界精修引擎，Grounding DINO 为冷启动标注辅助**。这与工业界在裂缝检测等“细粒度、非自然图像”任务上沉淀下来的“检测器自提示+轻量 SAM 微调”范式完全一致([arXiv: CrackESS](https://arxiv.org/html/2412.07205v3))。

## 5. 颜色确认与线路拆分

### 5.1 掩码内稳健取色：对抗染色的关键一步

染色问题的本质是：岩点表面的一部分像素不再代表岩点的真实颜色。因此取色算法必须对“部分像素被污染”稳健。实践中被验证有效的做法有三种，可叠加使用。其一，**直方图众数法**：NeuralClimb 在 HLS 空间对掩码内每个通道做宽度为 4 的分箱直方图量化，取出现次数最多的颜色组合作为岩点颜色——镁粉和鞋胶只污染部分像素，众数天然免疫([NeuralClimb](https://github.com/scsukas8/NeuralClimb))。其二，** erosion + 中位数**：对分割掩码先做一次形态学腐蚀（去掉边缘 2–3 像素的抗锯齿与阴影过渡带），再在 Lab 空间对剩余像素取逐通道中位数。其三，**核心区采样**：仅在距掩码边界最远的“骨架”区域采样颜色，进一步排除边缘污染。

色彩空间选择上，多篇攀岩项目一致弃用 RGB：NeuralClimb 用 HLS“加大线路之间的色相差异”([NeuralClimb](https://github.com/scsukas8/NeuralClimb))，UCSD 用 HSV 并指出“颜色在 HSV 中比在 RGB 中更易分离”([UCSD](https://kastner.ucsd.edu/ryan/wp-content/uploads/sites/5/2022/06/admin/rock-climbing-coach.pdf))。若追求与人眼感知一致的距离度量，CIELAB+CIEDE2000 是更严谨的选择，已有工作用它构建了 280 色的命名系统([arXiv](https://arxiv.org/html/2604.03235v1))。另外，跨照片的颜色一致性需要预处理配合：自动白平衡或灰世界校正可以显著降低不同灯光、不同手机之间的色偏；NeuralClimb 也指出同一算法换相机会有“过拟合到某台设备”的风险，攀岩馆内光照相对稳定是缓解因素([NeuralClimb](https://github.com/scsukas8/NeuralClimb))。

### 5.2 从岩点颜色到线路：聚类优先于分类

把岩点分到线路有两种范式。**固定类别分类器**（如 UCSD 的 11 类神经网络，准确率 99.3%）简单直接，但对“同馆相近色线路”和“不同馆色卡不同”两个问题无能为力，UCSD 自己记录了绿色/青绿色线路被合并的失败案例([UCSD](https://kastner.ucsd.edu/ryan/wp-content/uploads/sites/5/2022/06/admin/rock-climbing-coach.pdf))。**逐图聚类**（对当前照片所有岩点的颜色特征做 K-means/凝聚聚类）是更通用的方案：tonylay7 用 RGB K-means 分组线路并特判黑白（黑白点在色相上无意义，需用明度通道处理）([tonylay7](https://github.com/tonylay7/bouldering_route_classification))；UCSD 也明确指出颜色频率分析可以解决分类器的局限([UCSD](https://kastner.ucsd.edu/ryan/wp-content/uploads/sites/5/2022/06/admin/rock-climbing-coach.pdf))；tjtl 的技术博客同样把“HSV 或 Lab 空间的 K-means”列为朴素但可用的基线，同时指出“不同岩馆、不同厂商的颜色和形状都不同，算法需要自适应”([tjtl.io](https://blog.tjtl.io/bouldering-and-computer-vision/))。

工程上推荐**层次化策略**：第一步用凝聚聚类（无需预设 K，用 CIEDE2000 距离+自适应阈值剪枝）得到初始线路分组；第二步把聚类中心映射到人类可读的颜色名（红/蓝/荧光绿……）供界面展示；第三步处理两种结构性例外——**同色异线**（两个聚类中心在颜色上不可分但空间上明显是两条线：可叠加空间连通性/垂直分层等弱先验进行拆分提示，并把最终决定权交给用户）和**多色共用点**（一个岩点属于多条线路：数据结构上线路-岩点应为多对多关系）。ChalkGPT 还演示了第三条路线：用 CLIP（ViT-B/32）对每个岩点裁剪图做零样本颜色分类，这在无训练数据时可用，但单点推理成本高，更适合作为聚类结果的语义命名器而非逐点分类器([ChalkGPT](https://github.com/GabiShahmayster/ChalkGPT))。

## 6. 交互修正：从“自动结果”到“用户可信结果”

### 6.1 交互原语与对应算法

你设想的“用户圈出漏掉的点重新处理”对应交互式分割（interactive segmentation）这一成熟研究分支，可按交互原语映射到具体算法。**点选**（点击漏检岩点中心）：EdgeSAM/SAM 的点提示，或专用交互分割模型——SimpleClick（ViT 骨干）在 SBD 基准上达到 90% IoU 平均只需约 4.15 次点击，较前最优提升 21.8%，且提供了面向低端设备的 xTiny 变体([SimpleClick](https://pmc.ncbi.nlm.nih.gov/articles/PMC11378330/))；RITM（HRNet）系列同样是轻量级的成熟选择。**框选/圈选**（拖一个框或圈住区域）：SAM 的框提示，或经典 GrabCut——用户拖矩形框即可迭代提取前景，必要时用笔刷做局部修正([GrabCut, SIGGRAPH 2004](https://pub.ista.ac.at/~vnk/papers/grabcut_siggraph04.pdf))。**删除/合并/拆分**：纯掩码运算即可（合并=掩码并集，拆分=在用户划线处做分水岭切分），无需神经网络。

交互修正环节有一个容易被忽视但至关重要的性能设计：**图像编码缓存**。SAM 类模型的推理分为“图像编码”（重，一次性）和“提示解码”（轻，每次交互），EdgeSAM 在 iPhone 14 上图像编码仅 26 ms、提示解码为毫秒级([arXiv: EdgeSAM](https://arxiv.org/abs/2312.06660))。只要在照片加载时缓存图像嵌入，之后每一次用户点击都可以做到近乎即时的掩码返回——这正是“精细交互”体验流畅的技术基础。桌面端同理：SimpleClick 即使 ViT-H 模型单次点击也只需 132 ms、显存 3.22 GB([SimpleClick](https://pmc.ncbi.nlm.nih.gov/articles/PMC11378330/))。

### 6.2 修正结果的闭环利用

商业产品的交互设计验证了这条路径的产品形态：Stōkt 的流程是“拍照→自动检测岩点→随时编辑、移动或添加岩点”([Stōkt](https://play.google.com/store/apps/details?id=com.getstokt.stokt))；boardclimbs 的“Hector”检测器同样是拍照后自动找点([App Store](https://apps.apple.com/us/app/boardclimbs/id6499280509))；Crux 主打自动扫描且照片可复用不重扫([Mountain Project 论坛](https://www.mountainproject.com/forum/topic/126015086/crux-new-free-home-wall-app))；OwnClimb 则把检测能力做成 API，输出“多边形+置信度+主色”，并允许用户调置信度阈值在召回与精确率之间取舍([OwnClimb](https://ownclimb.com/))。这些产品的共同点是：**自动检测不求一次做对，而是通过低摩擦的修正交互收敛到用户满意**。

你的系统可以比这些产品更进一步：把每一次用户修正（新增的岩点掩码、被删除的误检、改判的颜色归属）持久化为标注数据，定期回流到检测模型的微调训练中。这形成了“用得越多、在你常去的岩馆越准”的数据飞轮，也是 antonylgs 项目中“模型辅助标注”思路的产品化延伸([LESSON.md](https://github.com/antonylgs/yolov11-climbing-holds-detector/blob/main/LESSON.md))。界面层的“选中线路彩色高亮、其余灰度”本身没有技术难点：对每条线路的岩点掩码取并集得到线路掩码，渲染时按线路掩码混合原图与灰度图即可，值得做的优化是把掩码预光栅化并缓存，以保证切换线路时零延迟。

## 7. 本地部署与性能工程

### 7.1 推理运行时与量化

“本地计算、性能高效”的目标在当前工具链下没有障碍。YOLO 系模型的部署路径已经非常成熟：PyTorch 训练后导出 ONNX，再按平台转换——iOS 用 CoreML（可利用 ANE 加速），Android/树莓派用 NCNN（腾讯的轻量推理框架，对 ARM 优化），桌面 NVIDIA 用 TensorRT（支持 FP16/INT8 量化与层融合），跨平台兜底用 ONNX Runtime([MDPI Electronics](https://www.mdpi.com/2079-9292/14/3/638), [NCNN 分析](https://blog.gopenai.com/yolo-models-on-ncnn-faster-or-slower-a-technical-breakdown-03d36612c921))。EdgeSAM 官方提供 ONNX/TensorRT 导出，CoreML 编译后在 iPhone 14 上实测 38.7 FPS([arXiv: EdgeSAM](https://arxiv.org/abs/2312.06660))。

性能预算可以这样估算：一张照片的处理=检测（YOLO11n-seg，CPU 约 66 ms；s 档约 118 ms）+每岩点取色与聚类（纯 numpy 运算，百个岩点 <10 ms）+EdgeSAM 图像编码（交互前预计算一次，iPhone 上 26 ms）。即纯 CPU 也能做到“拍照后一秒内出全图结果”；若整墙 4K 照片启用 SAHI 4–9 切片，延迟乘以切片数但仍在一两秒量级，且可以完全放在后台线程([Ultralytics 基准](https://github.com/eecn/yolov8-ncnn-inference), [TechnoLynx](https://www.technolynx.com/post/sahi-yolo-slicing-aided-inference-for-small-object-detection/))。内存方面，n 档 YOLO-seg 模型权重仅数 MB，EdgeSAM 约 40 MB 量级，移动应用包体完全可控。

### 7.2 推荐的整体架构与实施路线

下图汇总了调研结论所指向的推荐管线，五个环节与前文各章一一对应。

![推荐管线架构](fig_pipeline.png)

实施上建议分四个里程碑推进。**M1（管线打通，2–3 周）**：用 Roboflow/Kaggle 公开数据微调 YOLO11n-seg 单类检测器，接掩码内 Lab 中位数取色+凝聚聚类分线，做出“上传照片→分线路高亮”的最小闭环；此阶段不追求精度，追求全链路可运行。**M2（精度达标，4–6 周）**：采集 50–150 张目标岩馆照片，用初版模型预标+人工修正的方式建自有数据集，按照片划分训练集重训；接入 SAHI 处理整墙高分辨率照片；完成墙面主色对照过滤（把与墙面同色的“岩点”候选降权）等误检治理。**M3（交互修正，3–4 周）**：集成 EdgeSAM（缓存图像嵌入），实现点选补漏、框选重分割、删除/合并/拆分、改色与改线路归属；实现修正数据回流。**M4（打磨）**：性能压测与量化（INT8）、多照片/多角度支持、（可选）攀爬者遮挡场景处理。

这个路线刻意把 SAM 相关集成放在 M3 而非 M1：交互修正是体验倍增器但不是精度瓶颈的解药——检测主路的召回率才是地基。Crux 用户的反馈提供了真实世界的校准：自动检测对“与木质墙面同色的白色岩点”和“体积点上紧贴的两个岩点”仍会漏检或合并([Mountain Project 论坛](https://www.mountainproject.com/forum/topic/126015086/crux-new-free-home-wall-app))，这两类失败正是要靠自有数据微调（M2）和交互修正（M3）分别消化的。

## 8. 风险清单与开放问题

下表汇总主要风险及对策，供工程规划参考。

| 风险 | 证据/来源 | 缓解对策 |
|---|---|---|
| 与墙面同色的岩点漏检（白点白墙、木点木墙） | Crux 真实用户反馈([Mountain Project](https://www.mountainproject.com/forum/topic/126015086/crux-new-free-home-wall-app))；NeuralClimb 记录([GitHub](https://github.com/scsukas8/NeuralClimb)) | 自有数据定向补充此类样本；交互补标兜底；此类点在几何上仍有凸起阴影，可探索阴影/高光线索增强 |
| 相近色线路被聚类合并 | UCSD 绿色/青绿色失败案例([UCSD](https://kastner.ucsd.edu/ryan/wp-content/uploads/sites/5/2022/06/admin/rock-climbing-coach.pdf)) | 逐图自适应聚类+CIEDE2000 距离；合并结果允许用户一键拆分 |
| 同一颜色对应多条线路（同色异线） | 岩馆常见运营方式 | 颜色+空间联合分组，界面提供“该颜色有 2 条线路”的人工裁决入口；数据结构按多对多设计 |
| 大体积点上多个岩点粘连被合并 | Crux 用户反馈([Mountain Project](https://www.mountainproject.com/forum/topic/126015086/crux-new-free-home-wall-app)) | 交互拆分（划线+分水岭）；训练数据补充粘连样本 |
| 4K 整墙照片小岩点召回不足 | 小目标检测的普遍性问题([Labellerr](https://www.labellerr.com/blog/small-object-detection/)) | SAHI 切片推理或 1280 输入训练；代价为线性增长的延迟 |
| SAM 自动模式产生大量非岩点掩码 | SAM 无类别语义([arXiv](https://arxiv.org/pdf/2402.02352))；密集小物体漏检/合并记录([MDPI](https://www.mdpi.com/1999-4893/19/1/23)) | SAM 仅用于交互修正与边界精修，不进主检测路 |
| 跨岩馆/跨设备泛化差 | NeuralClimb 的相机过拟合警示([GitHub](https://github.com/scsukas8/NeuralClimb))；Roboflow 数据分布偏置 | 每接入新馆采集少量照片微调；白平衡/灰世界预处理；数据增强覆盖光照变化 |
| 公开数据集许可限制商用 | 数据集各自许可不同 | 逐个核对（CC BY 4.0 需署名）；长期以自标数据为主 |

另有两个开放问题值得在立项时想清楚。其一是**评估基准**：领域内尚无公开的标准岩点检测基准（斯德哥尔摩大学的论文正是为指出这一点而作([SU DiVA](https://su.diva-portal.org/smash/get/diva2:1955778/FULLTEXT01.pdf))），建议在 M2 阶段就冻结一批自有测试照片，用 mAP/召回率/线路分组准确率建立自己的回归基准，否则模型迭代无法量化。其二是**攀爬者入镜**：如果照片中有攀爬者遮挡岩点，检测会漏掉被挡住的点；ChalkGPT 用 SAM 2 分割攀爬者的思路可以迁移为“先分割出人形区域并从检测候选中剔除/标记”([ChalkGPT](https://github.com/GabiShahmayster/ChalkGPT))，但最省事的方案是引导用户拍无人照片，把遮挡场景留到后续版本。

## 9. 结论

回到最初的问题——“有没有论文、开源仓库、YOLO 或 SAM 这类模型可用”——答案是全面肯定的。**论文侧**，从 UCSD 的完整管线（检测 mAP 96.3%、颜色分类 99.3%）到海德堡的岩点+线路双任务分割、再到 2026 年 SSRN 上对本问题的形式化总结，学术脉络完整且结论一致：深度学习实例分割是岩点检测的标准答案，颜色处理应与检测解耦([UCSD](https://kastner.ucsd.edu/ryan/wp-content/uploads/sites/5/2022/06/admin/rock-climbing-coach.pdf), [GitHub: xiaoxiae](https://github.com/xiaoxiae/Indoor-Climbing-Hold-and-Route-Segmentation), [SSRN](https://papers.ssrn.com/sol3/papers.cfm?abstract_id=7124038))。**开源侧**，antonylgs 的 YOLOv11 项目提供了几乎可直接 fork 的训练管线与数据处理经验，tonylay7 提供了掩码→颜色→线路的算法原型，ChalkGPT 提供了 SAM2/CLIP 的组合示范，Roboflow 与 Kaggle 提供了冷启动数据。**模型侧**，YOLO11-seg 系列覆盖从 CPU 到 GPU 的各档性能需求，EdgeSAM 让 SAM 级交互分割在手机上实时可行，二者组合的“检测器自提示+轻量 SAM”架构已在工业界有成功先例([Ultralytics 基准](https://github.com/eecn/yolov8-ncnn-inference), [arXiv: EdgeSAM](https://arxiv.org/abs/2312.06660), [arXiv: CrackESS](https://arxiv.org/html/2412.07205v3))。**产品侧**，Stōkt、boardclimbs、Crux、OwnClimb 已经验证了“自动检测+交互修正”商业模式的成立，意味着竞争壁垒不在算法本身，而在交互体验、数据飞轮与岩馆生态。

你提出的“先轮廓检测、再颜色确认”的总体设计方向，与所有证据指向的最佳实践一致；需要修正的预期只有一处：颜色确认不应理解为“再用颜色验证一遍轮廓”，而应理解为“在轮廓内部做抗污染的稳健取色，再做逐图自适应聚类分线”。按第 7 节的四个里程碑推进，一个技术风险可控、体验可打磨的 MVP 是现实可行的。
